# Notion File 文件管理方案

## 目标

在不改变“文件存放于 Notion、桌面端维护本地索引”的核心架构下，把当前的基础目录浏览升级为可长期使用的个人云盘文件管理中心。

本轮优先解决三个问题：

1. 文件数量增加后，单纯依赖目录和名称很难定位内容。
2. 缺少批量操作，整理大量文件时需要逐个处理。
3. 缺少容量、重复文件和大文件视角，无法判断空间主要消耗在哪里。

## 设计原则

- **Notion 仍是远端事实来源**：不新增会导致旧数据库无法读取的强制字段。
- **智能分类由现有索引即时计算**：最近修改、大文件、重复文件不需要额外同步状态。
- **批量操作复用现有原子命令**：移动、删除和恢复仍经过后端路径校验及 Notion 远端更新。
- **避免破坏原有能力**：连接设置、传输中心、版本历史和传统同步继续通过经典界面提供。
- **大规模数据优先**：搜索范围、类型过滤、排序和全选均在本地索引上完成，避免不必要的 Notion API 请求。

## 本轮实施内容

### 1. 新文件管理中心

- 默认启动进入新的文件管理中心。
- 保留“经典功能”入口，原界面不删除。
- 根目录和子目录使用面包屑导航。
- 文件详情面板显示类型、大小、版本、时间、SHA-256 和 Notion 页面入口。

### 2. 智能分类

- 全部项目
- 全部文件
- 全部文件夹
- 最近 30 天修改
- 大于等于 100 MiB 的大文件
- 基于 SHA-256 的重复文件
- 回收站

智能分类只依赖现有 `DriveNode` 数据，不修改 Notion 数据库结构。

### 3. 搜索、过滤与排序

- 搜索名称、逻辑路径、MIME 类型和 SHA-256。
- 在目录视图中搜索时覆盖当前目录及全部子目录。
- 支持图片、视频、音频、文档、压缩包和其他文件过滤。
- 支持名称、修改时间、大小和类型排序。

### 4. 批量管理

- 当前列表全选或逐项多选。
- 批量移动。
- 批量移入回收站。
- 批量恢复。
- 选择文件夹时自动把子项折叠到根节点，避免对同一子树重复执行操作。

### 5. 容量与重复文件分析

管理中心顶部展示：

- 已索引总容量
- 文件和文件夹数量
- 重复文件估算占用
- 上传队列状态

重复占用按同一 SHA-256 文件组中除一份之外的文件大小估算。该值用于整理提示，不代表 Notion 账单或实际底层去重结果。

## 后续演进

### 元数据管理

在确认现有 Data Source 自动迁移策略稳定后，可增加收藏、标签、备注和业务分类字段。届时需要：

- 初始化时检查并补齐 Notion Data Source 属性。
- 本地 SQLite 和 Notion 页面属性双向同步。
- 标签过滤和收藏视图。

### 完整性中心

后续可增加：

- 本地索引与 Notion 页面数量差异检查。
- 缺失文件块、失效 Block ID 和孤立节点检测。
- 批量修复路径、父子关系和远端索引。
- 定期生成容量、重复率和失败传输报告。

## 验收标准

- 原有经典界面仍可正常打开。
- 前端构建通过。
- 新管理中心可从本地 SQLite 索引启动，不需要额外远端请求。
- 搜索、分类、过滤和排序不修改远端数据。
- 批量移动、删除和恢复继续调用现有后端命令，并在失败时逐项反馈。
- 上传队列事件能刷新文件列表和容量统计。
